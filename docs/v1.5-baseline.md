## Existing routes (API)

- `apps/api/src/numra_api/routes/people.py` — `POST /v1/people`, `GET /v1/people`,
  `GET /v1/people/{id}`, `PATCH /v1/people/{id}`, `DELETE /v1/people/{id}`.
  `PersonPatchRequest` only covers `current_first_names`/`current_middle_names`/
  `current_last_name`/`preferred_name` — **no birth-field editing exists yet** (Epic B).
- `calculations.py` — `POST /v1/people/{person_id}/calculations`,
  `GET /v1/calculations/{id}`, `GET /v1/people/{person_id}/timing`. **No list endpoint.**
- `reports.py` — `POST /v1/reports`, `GET /v1/reports/{id}`,
  `GET /v1/report-jobs/{id}`. **No list endpoint.**
- `relationships.py` — `POST /v1/relationships`, `GET /v1/relationships/{id}`.
  **No list endpoint**, and creation requires two `calculation_id`s directly (no
  person-based resolution).
- `exports.py`, `health.py`, `auth.py`, `account.py` — unaffected by V1.5 scope below.

## Existing routes (Web)

`apps/web/src/app/{dashboard,people,people/[id],people/new,analysis/[calculationId],
today,reports,reports/[reportId],relationships,relationships/[id],settings,
settings/privacy,login}` already exist. `/reports` and `/relationships` list pages
exist but are LocalStorage-driven (see below), not server-backed.

## LocalStorage dependency (Epic A target)

`apps/web/src/lib/local-calculations.ts`, `local-reports.ts`, `local-relationships.ts`
are the *only* way the frontend currently discovers that a calculation/report/
relationship exists for a person — there is no server list API to fall back to. A
second browser/device with an authenticated session but empty LocalStorage cannot see
any of this history today. `local-preferences.ts` (default person, view prefs) is fine
to keep — it's presentation-only.

## Database (already present, no new tables needed for Epic A/C)

`apps/api/src/numra_api/models/tables.py`: `User`, `Session`, `Person`, `NameIdentity`
(already has `kind`, `valid_from`/`valid_to` nullable, `created_at` — the schema
already supports Section 7's "recorded_at vs valid_from, never guess" semantics; no
migration needed for that, only API/UI work), `Calculation` (immutable snapshot,
confirmed never mutated — `repositories/calculations.py` has no update function),
`RelationshipComparison`, `Report`, `ReportSection`, `ReportJob`, `LLMGeneration`,
`Export`. Three migrations exist: initial schema, report-job retry/idempotency,
export file-size/error-code columns.

No `relationships` repository module exists yet — `routes/relationships.py` queries
`RelationshipComparison` directly via `db.get()`.

## i18n / language

No centralized i18n system exists. UI strings are hardcoded English inline in
components (confirmed via `apps/web/src/app/**`, `apps/web/src/components/**`).
Knowledge base content (`knowledge/de-v1.json`-style files) is already German —
Section 11's "UI locale is separate from knowledge/report language" concern is about
introducing a *UI* catalog without touching how report content is generated.

## PWA

No `manifest.json`/`manifest.webmanifest`, no service worker registration found under
`apps/web/src`. `apps/web/public/` currently has only `robots.txt` and
`src/app/icon.svg` (added during the P0/P1 hardening pass for `docker-build`'s
`COPY --from=build .../apps/web/public` step).

## Mobile navigation

Current navigation is `AppShell` (`apps/web/src/components/layout/app-shell.tsx`) —
desktop-oriented; no fixed bottom navigation for mobile viewports exists yet.

## Auth / sessions

`apps/api/src/numra_api/routes/auth.py` has register/login/logout/me. No
change-password route, no session-revocation/"logout all devices" route yet.

## Scope decision for this branch

Given the size of the full V1.5 directive (14 product epics plus i18n, PWA, mobile nav,
and a full test/doc pass), this branch prioritizes **Epic A (Server-authoritative
history)** as P0 — it is the explicit priority in the directive and the hard
prerequisite for the Report Library and Relationship Library epics. Additional epics
land as further commits/PRs as session budget allows; see the PR description for the
actual final scope delivered versus deferred.
